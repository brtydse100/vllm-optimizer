# v0.1.0a16

## Highlights

- Added adaptive benchmark repeat policies for evidence-driven measurement
  budgets.
- Improved repeat aggregation and ranking while retaining repeat-level
  provenance.
- Hardened reports and comparisons against incomplete evidence.

## Release artifacts

| Platform | Install |
| --- | --- |
| PyPI | `pip install "vllm-optimizer==0.1.0a16"` |
| Linux/WSL runtime | `pip install "vllm-optimizer[runtime]==0.1.0a16"` |

The universal wheel, source distribution, and SBOM are attached to the
release.

## Adaptive benchmark repeats

The new adaptive repeat policy can request more measurements when the current
evidence is too noisy or incomplete for a reliable decision. Configuration is
validated before execution, and repeat budgets are represented explicitly in
the run state and reports. Fixed repeat behavior remains available for users
who need a deterministic measurement budget.

Repeated experiments are ranked by arithmetic mean. Individual repeat results,
coverage, and eligibility remain available so the aggregate does not hide
failed or incomplete measurements.

## Reporting and evidence

- Comparisons now distinguish complete, workload-matched evidence from partial
  coverage and mark unavailable aggregates explicitly.
- Added evidence-aware comparison and leaderboard support.
- Refreshed the published RTX 3080 report examples and provenance to match the
  current results JSON and HTML report format.

## Packaging and documentation

- Made PyPI publishing safe to retry after a partial upload with
  `skip-existing` enabled.
- Expanded benchmark-repeat, configuration, reporting, and results guidance.

## Validation

The public and available private suites, package checks, lint, types, coverage,
strict documentation build, audit, and release workflow are run for this
release. Hardware smoke and real-backend validation remain dependent on the
manual GPU workflow.
